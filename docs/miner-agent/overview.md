# Miner Agent Overview

`miner-agent` is the node-side control-plane agent for decentralized miner deployments.

It is intended to run beside the model runtime and `dcgm-exporter`. In the Compose topology generated by `miner-cli`, the agent is configured through the `miner_client` block for backward compatibility with the earlier sidecar name.

## What It Does

On startup, `miner-agent`:

1. loads `${MINER_HOME}/config.json`
2. generates a new node identity and wallet identity when no config exists
3. starts a FastAPI diagnostics server
4. calls the miner registration endpoint
5. sends an initial heartbeat
6. repeats heartbeat on a fixed interval
7. pulls and answers challenges when registration or heartbeat responses require it

On every heartbeat, it collects:

- host CPU and memory snapshot
- GPU inventory from `nvidia-smi`, with a DCGM fallback
- local runtime health from `/health`
- served model IDs from `/v1/models`
- optional runtime load data from `/load`
- local DCGM Prometheus metrics from `/metrics`

## What It Does Not Do

`miner-agent` does not start, stop, or supervise the model runtime. Runtime lifecycle is handled by Docker Compose through `miner-cli`.

The agent also does not implement scheduling, billing, revenue settlement, or model routing. It only reports the local node state and answers control-plane verification challenges.

## Identity Model

The agent persists identity in:

```text
${MINER_HOME}/config.json
```

Persisted fields include:

- `node_id`
- `node_key_type`
- `node_public_key`
- `node_private_key`
- `wallet_key_type`
- `wallet_public_key`
- `wallet_private_key`
- `wallet_address`
- `created_at`

Identity details:

- `node_id` is derived from the Ed25519 public key as a libp2p-style Peer ID.
- challenge and control-plane payload signatures use the Ed25519 node private key.
- `wallet_address` is derived from a secp256k1 keypair as an EVM-style address.
- the identity directory is written with best-effort `0700` permissions.
- the identity file is written with best-effort `0600` permissions.

Mount `${MINER_HOME}` as a persistent volume when running in Docker. Losing this file creates a new node identity.

## Background Loop

The agent starts one background loop after identity initialization. Each loop iteration:

1. sleeps for `MINER_HEARTBEAT_INTERVAL_SECONDS`
2. registers again if the node is not registered
3. sends heartbeat
4. handles a challenge signal if the control plane returns one

HTTP failures are recorded in in-memory state and exposed through the local status API.
